# 可扩展边界、实现差异与实验原则

## 1. 第一原则：保持可修改

本版将模型、目标构造、训练策略、数据和后处理拆开。研究中常改的宽度、层数、预算、窗口、来源和细化器均有显式配置。ModelConfig 拒绝未知字段；训练 YAML 只由 engine 读取，不向模型隐式传入数据集状态。

不为第一版引入复杂注册框架管理所有算子。构造器接受 backbone/neck/head/reader/refiner 实例，简单配置决定已有变体；更大的结构变化可通过继承或组件替换完成，必须同步合同测试。

## 2. 新数据集

```python
from torch.utils.data import Dataset
from bcrnet.data.datasets import register_dataset

@register_dataset("my_rgb_dataset")
class MyDataset(Dataset):
    # __init__(root, annotations, image_size, training, mean, std, ...) 读取自有格式
    # __getitem__(i) 返回：
    # image: FloatTensor[3,H,W]；mask: BoolTensor[1,H,W]
    # target: boxes FloatTensor[N,4] 输入坐标 xyxy，labels LongTensor[N]，从 0 开始
    #         ignore_boxes FloatTensor[M,4]，original_boxes，以及完整 meta
    pass  # 文档接口示意；实际适配器须实现上述方法
```

此示意不是项目中的空实现。已有可运行 CocoDetectionDataset。自定义注册模块需在 build_dataset 之前显式 import，或在自定义入口调用；目前没有“扫描任意文件自动导入”的隐式机制。

训练/评估需要数据集暴露 num_classes、categories、category_to_label、label_to_category、annotation_path。现有 COCO evaluator 要求有 COCO GT manifest；若新数据无法提供该导出，应替换 evaluator，而不是假装通用评估已支持所有原始格式。

## 3. 替换模型组件

```python
from bcrnet import BCRNet, ModelConfig

cfg = ModelConfig(width=96, heads=4, budget=8)
model = BCRNet(cfg)  # 自动调整 FPN/adapter/head/router/refiner 的相关宽度
# model = BCRNet(cfg, backbone=YourBackbone(cfg), refiner=YourRefiner(cfg))
```

| 改动 | 必须保持或同步的合同 |
| --- | --- |
| Backbone | 返回 d1/c2/c3/c4/c5，stride=2/4/8/16/32；配置通道一致 |
| Neck | 返回 p2/p3/p4/t5，宽度 cfg.width，与相应网格对齐 |
| Head | 输入 N×d×h×w，返回 N×(C+4)×h×w；逐点一致性 |
| Reader | 返回 query/memory/valid/core/core_mask，BK 打包顺序不变 |
| Refiner | 输入 reader 的五项，输出 BK×d×m×m 残差 |
| Router | 返回 q/objectness/U/valid_windows；最终索引不重复 |
| 损失 | 保持每图坐标、mask、归一化合同，避免给 U 标签引入隐式尺度偏差 |
| 后处理 | head 的参数化或输出通道改变时同步解码与测试 |

增加 3×3 空间检测头时，必须读取额外 head halo，并保证训练/推理边界一致。若只是把现有 CenterHead 换成 3×3 然后对 8×8 核心预测，将出现 patch 边缘与整图不一致的问题。

新增时序/红外分支意味着更换当前研究任务，不应该悄悄塞入现有 RGB 单帧训练入口。多目标与多类别已留接口，但原 Anti-UAV 标注完整性不自动满足通用多目标评估。

## 4. 相对研究设计的实现选择

| 项目 | 当前明确实现 | 影响 |
| --- | --- | --- |
| 名称 | BCRNet，原 TSCRNet-V2 方案留作历史原件 | 文档统一新名称 |
| 均值/标准差 | 默认 ImageNet 常数，可配置 | 未对真实训练集统计；无预训练权重 |
| 增强 | 仅水平翻转 | 不混入多种增强效果，后续独立消融 |
| 精度接口 | 原始 logits 与 criterion/postprocess 分离 | 可复用中间结果、替换监督 |
| 稀疏执行 | 选中窗口 gather 后投影和细化 | 无专用 CUDA kernel，真实延迟需 profile |
| 分块 | attention 按 BK 分块，reader 仍整体打包 | dense 模式峰值显存并非严格与 chunk 成正比 |
| 无效窗口 | -1 占位、残差清零、回写不污染 | 部分占位仍计算，预算只保证上限 |
| 注意力 | PyTorch SDPA + 相对偏置 | 后端选择取决于输入/设备，不承诺 FlashAttention |
| 模型归一化 | 稠密路径 BN；token LN；conv 细化 GN | 小 batch BN 需要实验，冻结时禁止统计漂移 |
| 优化器/训练 | 单设备 AdamW、分阶段 cosine、AMP、无 EMA 模型 | 并非完整大规模训练平台 |
| 工程接口 | Python、CLI、COCO 导出 | 暂无 DDP/ONNX/TensorRT/视频追踪/自动续抽 |
| 质量评估 | 标准 COCO 与基础路由/负帧诊断 | 完整研究指标仍需扩展 |

## 5. 避免错误结论的原则

1. **基础对照同训练条件。** 相同 Backbone/Neck/head/监督与数据；清楚区分“同 checkpoint 切换模式”与“各模式独立训练”。
2. **先验证细化能力，再验证路由价值。** 全覆盖或训练 oracle 也不改善时，不应依靠更复杂 U 来挽救 story。
3. **真正计算稀疏。** 测试 base 的执行 hook、只对选中核心投影、检查未选区域不变；不要先算 dense 再 mask。
4. **区分精度与覆盖。** 目标核心被选不代表检测正确；U 标签改善训练 loss 不代表改善 AP。
5. **负帧与同源泄漏可改变结论。** 不删掉所有负帧、不过度重复相邻帧、保留原 test、不用 test 选择 K。
6. **速度要测整条路径。** 本机初测 full 的 MAC 仅比 base 高约 11.6%，模型耗时却约为 2.7 倍，说明算子调度/访存是实际限制；不能只展示漂亮 MAC。
7. **变化可追溯。** 配置快照、manifest hash、checkpoint schema、随机种子和原图坐标元数据必须随结果留存。
8. **不虚构预训练或结果。** 当前工程验证不是有效性实验；未获得真实 Anti-UAV AP。

## 6. 建议后续迭代顺序

先运行抽帧 dry-run 与人工叠框审核，统计输入尺度、负帧、序列和划分；随后训练基础模型，验证过拟合小训练子集与负帧输出行为。再验证 dense/同预算普通卷积细化是否带来稳定收益，之后才比较 q、U、full 和多个 K。

速度优化优先定位 router 的窗口统计、gather/transpose、SDPA 小矩阵和 scatter；考虑融合统计、减少 layout 变换、按图块打包、复用 memory 投影。每次优化都要验证边界 mask、梯度与未选区域行为。若低预算上下文细化仍无实际优势，应接受更简单的静态变体。

论文最终应展示至少多个随机种子或按拍摄组 bootstrap，清楚区分官方与 group 划分、原图小目标与输入 tiny 分桶、单帧检测与跟踪任务，并报告同硬件端到端延迟。研究价值由这些实验支撑，不由模块数量支撑。
