# 04 首次训练与断点恢复

## 1. 不要把第一次正式训练当作调试

训练分三层推进：先验证代码入口，再验证一个小批次能前后向，最后才跑完整 Anti-UAV。这样遇到问题时容易区分环境、数据和模型原因。

## 2. 第一步：合成数据 CPU 冒烟

```powershell
Set-Location 'F:\antiuav\TSCRNet\BCRNet-main'
conda activate bcrnet
python scripts/create_synthetic_dataset.py --output runs/tutorial_synthetic_data
python -m bcrnet train --config configs/smoke.yaml --data runs/tutorial_synthetic_data/data.yaml --output runs/tutorial_smoke --device cpu --max-batches 1
```

这个过程只验证数据读取、前向、损失、反向、checkpoint 和验证入口。合成图片上的 AP 没有研究意义。

正常输出目录包括：

```text
runs/tutorial_smoke/
  config.json
  metrics.jsonl
  last.pt
  best.pt          只有指标刷新时保存
```

训练过程会在终端显示 tqdm 进度条，包含当前 epoch、阶段、batch、平均 loss 和学习率。每个 epoch 结束后还会输出一行 JSON；完整记录保存在 `metrics.jsonl`。

## 3. 第二步：真实数据单批次冒烟

确认抽帧数据已经人工检查后，用新的目录：

```powershell
python -m bcrnet train `
  --config configs/bcrnet.yaml `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --output runs/antiuav_smoke_real `
  --device cuda `
  --max-batches 1 `
  --stop-after-epochs 1
```

PowerShell 的反引号必须位于行尾，后面不能有空格。也可以把命令写在一行。

检查：loss 是否有限；显存是否足够；日志是否出现 AMP 连续溢出；val 是否至少读取一个 batch；last.pt 是否生成。`max-batches` 会得到部分验证，只能用于诊断，不能写进论文结果。

## 4. 第三步：正式完整训练

```powershell
python -m bcrnet train `
  --config configs/bcrnet.yaml `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --output runs/bcrnet_full_seed42 `
  --device cuda `
  --mode full `
  --workers 0
```

默认从随机初始化开始，100 epochs、batch size 2、AMP、AdamW。`configs/bcrnet.yaml` 默认每 1 个 epoch 验证一次，连续 10 次验证没有提升时早停；始终保存 `last.pt`，监控指标 `AP50_95` 刷新时保存 `best.pt`。

也可以在命令行覆盖训练控制参数：

```powershell
python -m bcrnet train `
  --config configs/bcrnet.yaml `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --output runs/bcrnet_full_seed42 `
  --device cuda `
  --val-interval 2 `
  --patience 8 `
  --min-delta 0.001 `
  --monitor AP50_95 `
  --progress
```

`--no-progress` 可以关闭实时进度条，但不会关闭 `metrics.jsonl`。命令行参数优先于 YAML 参数。

完整 A/B/C/D 训练中，A-C 的验证主要用于观察阶段变化；默认从 D 阶段开始更新 `best.pt` 和计算早停。若只训练单个阶段，早停阶段会自动切换为该阶段，也可以用 `--early-stop-stage` 显式指定。

Windows 首次建议 workers=0。确认稳定后可以尝试 2 或 4，但每个正式实验固定同一值。batch size 不够显存时可命令行加 `--batch-size 1`；当前训练器没有梯度累积，所以改变 batch 会改变优化过程。

## 5. A/B/C/D 四阶段是什么意思

```mermaid
flowchart LR
    A["A 基础检测与 tiny"] --> B["B 冻结基础，训练局部细化"]
    B --> C["C 冻结基础/细化，训练收益 U"]
    C --> D["D 按可部署路由联合微调"]
```

默认 100 epochs 分为 40/25/10/25：

| 阶段 | 更新的部分 | 训练选窗 |
| --- | --- | --- |
| A | Backbone、Neck、Adapter、基础头、tiny head | 不执行局部细化 |
| B | Reader、Refiner | 覆盖候选 + 少量 GT 核心 + 随机补齐 |
| C | Router 的收益分支 | 以局部细化损失改善监督 U |
| D | 全模型 | 使用命令指定的可部署 mode |

B/C 的 GT 引导只存在于训练函数，正常 `model.forward` 和评估不使用 GT 选窗。D 阶段才真正让完整推理路径联合适应。

## 6. 训练配置逐项解释

```yaml
training:
  epochs: 100
  batch_size: 2
  val_interval: 1
  patience: 10
  min_delta: 0.0
  monitor: AP50_95
  early_stop_stage: D
  progress: true
  seed: 42
  amp: true
  amp_init_scale: 16
  lr: 0.001
  weight_decay: 0.01
  grad_clip: 10.0
  probe_probability: 0.1
  stage_lr_multipliers: {A: 1.0, B: 0.5, C: 1.0, D: 0.1}
```

- seed 控制 Python、NumPy、PyTorch、DataLoader 和路由采样；
- AMP 降低显存并提高 GPU 吞吐，梯度缩放状态保存在 checkpoint；
- 每个阶段使用基础 lr 乘阶段系数；
- grad_clip 防止梯度范数异常增大；
- D 阶段按 probe_probability 对未选窗口做额外收益探测，只用于训练 U，不进入推理。

训练控制参数的含义：

- `val_interval`：每 N 个 epoch 验证一次；阶段切换和最后一个 epoch 会强制验证；
- `patience`：连续多少次验证没有超过 `min_delta` 才早停，设为 0 表示关闭早停；
- `min_delta`：监控指标被认为“有提升”所需的最小增量；
- `monitor`：用于 `best.pt` 和早停的验证指标，支持 `AP50_95`、`AP50`、`AP75`、`AP_small_original_COCO` 和 `AR100`；
- `early_stop_stage`：早停开始生效的阶段；完整 A/B/C/D 训练默认是 D，避免 warm-up 阶段提前截断；
- `progress`：是否显示 batch 级实时进度条。

`loss` 下四个 weight 控制基础、tiny、utility 与残差项。开始时不要同时调结构和多个 loss 权重，否则无法解释变化来源。

## 7. 怎样看 metrics.jsonl

每行对应一个 epoch，是独立 JSON。典型字段：

- `epoch`：从 1 开始显示；
- `stage`：当前 A/B/C/D；
- `train.loss` 及各分项：该 epoch 的 batch 平均；
- `validated`：本 epoch 是否执行验证；
- `val.AP50_95/AP50/AP75`：验证精度；没有验证的 epoch 中 `val` 为 `null`；
- `monitor_value`、`best_metric`、`best_epoch`：当前监控值和最佳记录；
- `bad_validations`、`patience`、`early_stopping`：早停计数和是否触发；
- `val_interval`：该 run 使用的验证周期；
- `val.negative_frame_false_alarm_rate`：阈值 0.25 下负帧误报率；
- `val.tiny_gt_core_coverage`：tiny 目标中心是否落在选中核心中，只是路由诊断；
- `amp_skipped_updates`：因非有限梯度被跳过的更新次数；
- `seconds`：该 epoch 总耗时。

不同阶段的总 loss 组成不同，不能只看 loss 是否连续下降。B/C 切换时 loss 量纲变化是正常现象。模型选择以预先确定的验证指标为准，默认 checkpoint 规则是 AP50_95。

如果希望只看 loss 变化，可以在另一个 PowerShell 窗口观察追加日志：

```powershell
Get-Content runs/bcrnet_full_seed42/metrics.jsonl -Wait
```

实时进度条适合观察当前 batch；`metrics.jsonl` 适合按 epoch 保存和后处理绘图。两者都不会改变模型 forward 或 loss。

## 8. 中断后怎样继续

在 epoch 边界恢复：

```powershell
python -m bcrnet train `
  --config configs/bcrnet.yaml `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --output runs/bcrnet_full_seed42 `
  --device cuda `
  --mode full `
  --workers 0 `
  --resume runs/bcrnet_full_seed42/last.pt
```

resume 会恢复权重、优化器、学习率、AMP、损失内部状态、随机数和阶段进度。配置、schedule、数据标注指纹、batch、workers、mode 等必须与 checkpoint 一致。恢复时不要修改 YAML。

同时会恢复 `val_interval`、`patience`、`min_delta`、`monitor`、最佳指标和连续未提升次数，因此早停计数不会因为恢复而重置。恢复仍然以 epoch 边界为单位；一个 epoch 中途终止时，最多损失当前 epoch 的进度。

如果你确实要改结构或训练配置并开始新实验，使用新目录和 `--weights`：

```powershell
python -m bcrnet train `
  --config configs/ablations/no_context.yaml `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --output runs/ablation_no_context_seed42 `
  --device cuda `
  --weights runs/bcrnet_full_seed42/best.pt
```

weights 只加载名称和形状兼容的张量，优化器与进度重置。它属于 warm start，不是继续同一实验。结构消融采用 warm start 还是独立随机训练，必须在实验方案中提前统一。

## 9. 常见训练异常

| 现象 | 先检查什么 | 处理原则 |
| --- | --- | --- |
| CUDA out of memory | batch、输入尺寸、dense mode | 先降 batch；记录变化，不要静默改配置 |
| loss 为 NaN/Inf | 标注框、学习率、AMP skip | 先查坏框和日志，不把错误 epoch 当有效结果 |
| AP 一直接近 0 | 叠框、类别映射、预测可视化 | 尝试小子集过拟合来区分数据与容量问题 |
| resume mismatch | YAML、data、workers、batch、mode | 保持旧实验不变，变更时用新目录 + weights |
| 输出目录非空 | 是否误用旧实验目录 | 为新实验换目录；只有合法恢复才用 resume |
| 过早早停 | val_interval、patience、monitor、验证集规模 | 先确认验证周期和监控指标，再提高 patience；不要用 test 调参 |
| 训练很慢 | workers、GPU 利用率、数据解码 | 先测量，不在消融中临时改变多个条件 |

正式长跑前建议做一个小训练子集过拟合实验：模型如果无法在极少量样本上明显降低检测损失，优先排查数据坐标、标签生成和优化设置。
