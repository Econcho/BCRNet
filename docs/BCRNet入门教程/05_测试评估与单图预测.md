# 05 测试、评估与单图预测

## 1. 三个容易混淆的词

训练集用于更新权重；验证集用于选择 checkpoint、超参数和消融方案；测试集用于方案冻结后的最终一次评估。训练过程中每个 epoch 自动评估的是 val。

单图预测只展示模型对某张图的输出，不能代替数据集指标。benchmark 测模型执行成本，也不等于检测精度评估。

## 2. 先在验证集评估

```powershell
python -m bcrnet evaluate `
  --checkpoint runs/bcrnet_full_seed42/best.pt `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --split val `
  --output runs/eval_full_seed42_val `
  --device cuda `
  --mode full `
  --batch-size 1 `
  --workers 0
```

输出目录必须为空或不存在，包含：

- `metrics.json`：汇总指标；
- `detections.json`：COCO 格式预测框，用于进一步分析。

调试时可以加 `--max-batches 2`，但结果会标记 `partial_evaluation=true`，不能用于正式对比。

## 3. 指标如何理解

| 字段 | 含义 | 使用注意 |
| --- | --- | --- |
| AP50_95 | IoU 0.50:0.95 的 COCO 平均 AP | 默认模型选择主指标 |
| AP50 | IoU=0.50 AP | 对定位误差较宽松 |
| AP75 | IoU=0.75 AP | 更强调精确定位 |
| AP_small_original_COCO | 原图 area<32² 的 COCO small AP | 与 BCRNet 输入 tiny 定义不同 |
| AR100 | 每图最多 100 检测的平均召回 | 观察漏检倾向 |
| negative_frame_false_alarm_rate | 负帧中至少有一个 score≥0.25 框的比例 | 反无人机误警很关键 |
| false_boxes_per_negative_frame | 每个负帧的平均误框数 | 区分少量与大量误报 |
| gt_core_coverage | 所有 GT 中心被选窗覆盖的比例 | 路由诊断，不等于检测召回 |
| tiny_gt_core_coverage | 输入 tiny GT 的选窗覆盖率 | 只说明路由是否看到目标核心 |
| selected_windows_per_image | 每图实际选窗数 | 检查 K 与有效区域影响 |
| model_ms_mean | 评估循环中的模型平均时间 | 含冷启动扰动，不是正式速度基准 |

如果 full 的选窗覆盖率很高但 AP 没改善，问题可能在局部细化；如果 dense 能改善而 full 不能，问题更可能在路由；如果 base 就无法学到目标，先修基础检测和数据。

## 4. 同一个 checkpoint 切 mode 有什么意义

```powershell
python -m bcrnet evaluate --checkpoint runs/bcrnet_full_seed42/best.pt --data data/antiuav_rgb_official_v1/data.yaml --split val --output runs/eval_sameckpt_base --device cuda --mode base
python -m bcrnet evaluate --checkpoint runs/bcrnet_full_seed42/best.pt --data data/antiuav_rgb_official_v1/data.yaml --split val --output runs/eval_sameckpt_full --device cuda --mode full
```

这个比较回答“同一组权重打开局部路径后发生什么”，适合机制诊断。它不能替代独立训练消融，因为 full 训练过程已经改变共享 Backbone 和 head。论文主要表格应使用预先规定的独立训练协议，同 checkpoint 切 mode 可作为补充分析。

## 5. 单图预测

```powershell
python -m bcrnet predict `
  --checkpoint runs/bcrnet_full_seed42/best.pt `
  --image 'F:\antiuav\TSCRNet\BCRNet-main\data\antiuav_rgb_official_v1\images\val\train_example\000100.jpg' `
  --output runs/predict_example_seed42 `
  --device cuda `
  --mode full `
  --score 0.25
```

输出：

- `prediction.jpg`：在原图上画红框和分数；
- `prediction.json`：原图坐标下的 boxes、scores、labels 和类别表。

`--score` 只影响单图展示阈值。评估内部需要较低预筛阈值来计算完整 PR 曲线，不能把二者当成同一个超参数。

单图出现空预测是合法结果。反无人机场景应同时查看正帧漏检和负帧误报，不能只挑表现好的图片展示。

## 6. 最终测试集评估

完成以下事项后才能使用 test：

- 数据采样和 split 已冻结；
- 主模型结构、K、halo、输入尺寸和训练配置已冻结；
- best checkpoint 的选择只依据 val；
- 消融结论已在 val 完成；
- 需要报告的随机种子规则已经确定。

然后运行：

```powershell
python -m bcrnet evaluate `
  --checkpoint runs/bcrnet_full_seed42/best.pt `
  --data data/antiuav_rgb_official_v1/data.yaml `
  --split test `
  --output runs/final_test_full_seed42 `
  --device cuda `
  --mode full
```

不要根据这次 test 结果再选择 K 或换 best checkpoint。如果必须修改方案，应明确开启新一轮研究，并承认原 test 已参与开发决策。

## 7. 速度与计算量是另一组测量

不涉及任何执行优化时，使用原 BCRNet benchmark 比较模型 mode 或结构：

```powershell
python -m bcrnet benchmark `
  --config configs/bcrnet.yaml `
  --checkpoint runs/bcrnet_full_seed42/best.pt `
  --output runs/benchmark_full_seed42.json `
  --device cuda `
  --mode full `
  --amp `
  --warmup 20 `
  --iterations 100
```

该命令统计模型 forward，排除读图、CPU 到 GPU、解码和 NMS。正式论文速度应再补端到端时间，并固定 GPU、电源模式、温度、batch、输入尺寸、AMP 和预热次数。

参数量属于模型容器；即使 base 不执行细化模块，容器仍持有这些参数。MAC 统计只覆盖实现中的主要算术，不包含排序、索引、激活、归一化和访存，所以它不能代替真实延迟。
