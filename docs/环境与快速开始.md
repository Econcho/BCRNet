# 环境与快速开始

第一次使用建议直接按 [BCRNet 从零入门教程](BCRNet入门教程/README.md) 的顺序操作；本文保留为紧凑命令参考。

## 1. 已完成的环境

| 项目 | 本机实际值 |
| --- | --- |
| Anaconda | D:\anaconda3 |
| 环境名 / 路径 | bcrnet / D:\anaconda3\envs\bcrnet |
| Python | 3.11.16 |
| PyTorch | 2.7.1+cu128 |
| torchvision | 0.22.1+cu128 |
| GPU | NVIDIA GeForce RTX 3060 Laptop GPU，6 GB |
| 驱动 | 596.08 |
| 项目安装 | pip editable，含 data/dev extras |

PyTorch/torchvision 采用[官方对应版本与 CUDA 12.8 安装源](https://pytorch.org/get-started/previous-versions/)，不是宣称使用最新版。PyTorch wheel 自带所需 CUDA 运行库，不要求另行编译 CUDA 算子。系统 nvidia-smi 显示的 CUDA 支持版本不等于 wheel 的 CUDA 版本。

environment.yml 定义基础 Conda 环境；requirements-lock.txt 固定本次 Windows 环境实际 pip 依赖（排除 editable 项目本身）。其他平台/显卡应选择对应的官方 PyTorch wheel，不保证这份 Windows 环境锁在所有平台原样复现。

## 2. 在 PowerShell 7 中使用

全部命令按 **pwsh.exe / PowerShell 7** 编写。当前环境已经创建，日常使用不需要再次 create。

```powershell
Set-Location 'F:\antiuav\TSCRNet\BCRNet-main'
conda activate bcrnet
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python -m bcrnet --help
```

如果当前 PowerShell 会话没有 conda activate 支持，可直接调用环境 Python，不必修改全局 shell 配置：

```powershell
& 'D:\anaconda3\envs\bcrnet\python.exe' -m bcrnet --help
```

在另一台具备合适 NVIDIA 驱动的机器上重建环境：

```powershell
conda env create -f environment.yml
conda activate bcrnet
python -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e '.[data,dev]'
python -m pip check
```

严格重建本次 pip 版本可在安装对应 CUDA wheel 后，使用 requirements-lock.txt 和官方 cu128 extra index，再 editable 安装本项目。依赖锁包含平台相关包，应先审查目标环境。没有自动下载预训练权重；默认随机初始化。

## 3. 数据准备

先读 [数据集与抽帧策略](数据集与抽帧策略.md)。真实抽帧脚本此次未运行。抽帧成功后 data/antiuav_rgb/data.yaml 是可直接传给训练入口的配置。

## 4. 正式训练与继续训练

```powershell
python -m bcrnet train --config configs/bcrnet.yaml --data data/antiuav_rgb/data.yaml --output runs/bcrnet_v01 --device cuda

# 在 epoch 边界恢复；schedule、配置、数据 manifest 等必须匹配
python -m bcrnet train --config configs/bcrnet.yaml --data data/antiuav_rgb/data.yaml --output runs/bcrnet_v01 --device cuda --resume runs/bcrnet_v01/last.pt
```

默认 100 epochs、batch=2、workers=0、AdamW、AMP、640 输入，每轮验证一次；完整 A/B/C/D 训练在 D 阶段连续 10 次验证没有提升时早停，并显示 batch 级 tqdm 进度条。batch=2 是保守起点，不代表对本机吞吐最优；显存充足可提高并记录配置。Windows 数据进程默认 0，明确需要时用 --workers 增加。训练只有随机水平翻转，暂未加入 Mosaic、MixUp、EMA 模型、预训练、DDP 或累积梯度。

默认每个 epoch 验证 val，保存 last.pt，AP50_95 改善时保存 best.pt。`--val-interval N` 可以改为每 N 轮验证；最后一轮和阶段切换仍会验证。`--patience N` 控制早停次数，`--patience 0` 关闭早停。输出 config.json、metrics.jsonl，记录阶段、loss、AMP scale/跳过更新次数、验证指标、早停计数和耗时。默认禁止复用非空 run 目录，resume 除外。resume 使用旧 checkpoint 而同目录日志已经更新到更后 epoch 时拒绝继续，避免混写。

**resume 保持原实验；weights 开启新实验**：

```powershell
python -m bcrnet train --config configs/bcrnet.yaml --data data/antiuav_rgb/data.yaml --output runs/new_experiment --weights runs/bcrnet_v01/last.pt --device cuda
```

weights 只加载同名同形状模型张量，输出 warm_start.json；优化器、阶段进度和随机状态重置。修改类别数量时同形状检查不等于语义相容，必须核对类别映射与 head，不能默认迁移原分类头。

## 5. 评估与单图推理

```powershell
python -m bcrnet evaluate --checkpoint runs/bcrnet_v01/best.pt --data data/antiuav_rgb/data.yaml --split test --output runs/test_full --device cuda --mode full
python -m bcrnet evaluate --checkpoint runs/bcrnet_v01/best.pt --data data/antiuav_rgb/data.yaml --split test --output runs/test_base --device cuda --mode base

python -m bcrnet predict --checkpoint runs/bcrnet_v01/best.pt --image 'F:\images\example.jpg' --output runs/prediction_example --device cuda --score 0.25
```

评估保存 metrics.json 和 COCO detections.json；推理保存原图坐标 prediction.json 与叠框 prediction.jpg，不改源图片。前处理配置和类别映射从 checkpoint 读取。预测可为空，不默认只取一个目标。

评估当前为 FP32；训练 AMP 与 benchmark --amp 不会自动改变评估精度。验证循环内的首次调用含冷启动，不能把其 model_ms_mean 当作稳定部署延迟。

## 6. 计算量与测速

```powershell
python -m bcrnet benchmark --config configs/bcrnet.yaml --output runs/bench_full.json --device cuda --mode full --amp --warmup 20 --iterations 100
python -m bcrnet benchmark --config configs/bcrnet.yaml --output runs/bench_base.json --device cuda --mode base --amp --warmup 20 --iterations 100
```

未传 checkpoint 时用随机权重，只验证执行成本。传 --checkpoint 则使用该模型及前处理尺寸。输出 batch 平均/p50/p95 延迟、吞吐、参数数、PyTorch 分配显存峰值，以及真实执行的 Conv/Linear/QK/AV MAC 统计。

计时包括模型中的路由、gather、细化、scatter；不包括读取图像、预处理、CPU→GPU、解码与 NMS。MAC 统计不计归一化、激活、softmax、排序、索引和访存，1 MAC 约对应 2 次浮点算术操作。总参数数是整个 BCRNet 容器，base mode 仍持有未执行模块的参数。

正式速度比较需要固定硬件、电源/温度、输入、batch、AMP、预热、实现和后处理，报告端到端时延。不能只根据参数/MAC 判断快慢。

## 7. 合成数据与测试

下面会生成程序绘制的小图，仅用于接口测试，无 Anti-UAV 数据读取：

```powershell
python scripts/create_synthetic_dataset.py --output runs/my_synthetic
python -m bcrnet train --config configs/smoke.yaml --data runs/my_synthetic/data.yaml --output runs/my_smoke --device cpu --max-batches 1
python -m bcrnet evaluate --checkpoint runs/my_smoke/last.pt --data runs/my_synthetic/data.yaml --output runs/my_smoke_eval --device cpu
```

--max-batches 限制每个训练 epoch 和验证的批次数，会明确记录 partial_evaluation。--stop-after-epochs N 用于在既定 schedule 中暂停，之后 resume；它不改变总训练计划。合成训练的 AP 无研究意义。

```powershell
python -m pytest -q
python -m ruff check src scripts tests
python -m ruff format --check src scripts tests
python -m compileall -q src scripts tests
python scripts/validate_cuda.py
```

若机器默认 pytest 临时目录权限异常，可用 **新的项目内专用目录**运行，例如 --basetemp=.pytest-check-local。pytest 可能清理该专用目录，不能把数据/项目根目录传给 --basetemp。CUDA 验证脚本只用随机张量，写 runs/validation/cuda_training.json。
